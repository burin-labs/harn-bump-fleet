The release audit validate->repair-with-feedback loop now runs on harn's canonical `workflow_run_repair` primitive (inline executor + retry-context feedback) instead of a hand-rolled `while` loop, completing the cutover the v0.9.12 rearch wave annotated. Behavior is unchanged: the loop still runs at most 3 attempts, stops on the first clean audit, threads each attempt's findings into the next attempt's repair prompt, and returns the same `initial-review` / `validation-repair-N` attempt records downstream consumers depend on.
