- The release pull request now opens unarmed, and the tag watch arms its merge only when `origin/main` is still the commit the release certified and GitHub reports the pull request would merge now. When main moved first the watch takes any armed merge back and ends the run with nothing merged, so main keeps its development version and a fresh cut at the new head is admissible, instead of the release merging at an uncertified base and stranding a bumped main with no tag. A release already in that stranded state is recovered by `recover-release-publication.yml` in its new `tag-stranded-main` mode, which tags the stranded merge commit only when that commit's tree is the certified one, or differs from it only in paths certification does not depend on.
