- A release no longer needs anyone to freeze the default branch while it certifies. The release pull request opens unarmed and the release merges it itself, under the pull request's exact head lease, once it has proved what it is about to ship: the certified tree plus commits that passed main's own required checks, read from the branch's rulesets and resolved per commit against both the commit and its pull request head, reduced to the latest run per name. A drifted commit carrying a red or unreported required check stops the release with nothing merged, so main keeps its development version and a fresh cut stays admissible. The lanes only a release runs, computed from workflow triggers rather than a maintained list, then run once on the merged main commit before the tag, because the tag is the publication act and an unpublished bump is a revertible commit. If one of them fails, the release opens the revert pull request itself, restoring the development version and the changelog fragments, and reports a deferral naming the drifted commits and the check that stopped it. Every drifted commit, check conclusion, and post-merge lane result is a required typed field in the release receipt, and the tag gate accepts a merged tree only where that record accounts for the difference.
