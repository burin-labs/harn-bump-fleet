- A release no longer needs anyone to freeze the default branch while it certifies. The release pull request opens unarmed and the release merges it itself, under the pull request's exact head lease, once it has proved what it is about to ship: the certified tree plus commits that passed main's own required checks, read from the branch's rulesets and resolved per commit against both the commit and its pull request head. A drifted commit carrying a red or unreported required check stops the release with nothing merged, so main keeps its development version and a fresh cut stays admissible. Drift that reaches paths only the release's own lanes cover, computed from workflow triggers rather than a maintained list, has those lanes run on the tree that will ship, bounded at three attempts. Every drifted commit and check conclusion is recorded in the release receipt, and the tag gate now accepts a merged tree only where that record accounts for the difference. A release whose bump merged without a tag is recovered by `recover-release-publication.yml` in its new `tag-stranded-main` mode.
