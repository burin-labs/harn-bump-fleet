The supersede advisory now states what superseding costs. Following the advice
is what invalidated it: superseding mints a second immutable attempt, and if
that run then fails for any unrelated reason the version holds two, at which
point the same command form fails with `selected 0 immutable attempts`. Both
messages were correct for their own state, but the second surfaces at the
*next* recovery, so the connection to the first was not obvious — recovering
v0.10.53 walked into it across three runs.

The advisory now names the cost and the abandon harness up front, which is the
only place it is cheap to learn. The resume refusal carries it too, since that
is the whole screen an operator sees before the run stops.
