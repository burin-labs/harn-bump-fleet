A failed hosted release run now leaves a typed receipt naming the precondition that failed and the exact re-dispatch that would retry it, instead of a red workflow conclusion somebody has to open and read. The run records the closed input set it was dispatched with, because the Actions API does not report it, and a terminal finalizer pairs that with the run's failing step. A failure the same inputs would repeat, and a step no registry row names, both escalate rather than defaulting to a retry.
