Add `--github-signed-commit`, which has the release harness create its release commit through `createCommitOnBranch` rather than local `git commit`, and asks GitHub itself whether that commit counts as signed. `hosted-release.yml` passes it: the committer there is a GitHub App bot, and GitHub cannot attribute a signing key to one, so a locally signed release commit is refused by a ruleset requiring signatures no matter which key made it.
