- A release now reads the lanes only a release runs from the drifted commit's own pull request, rather than running them itself. Once those lanes run on ordinary code pull requests, a commit that reached main has already been tested by them, and the release merges on that evidence. A lane that is still running is a wait, not a refusal, because it is not a check the branch requires and it finishes on its own; a lane that actually failed still stops the cut with nothing merged. A drifted commit owes a lane an answer only when it touched a path that lane bears on, so a fragment- or docs-only commit is never waited on for a workspace test run its pull request never triggered. When the receipt records a green release-only result for every commit that owed one, the pre-tag run of those lanes is skipped by a named verdict rather than repeated.
