Release prepare now executes a shielded copy of the exact-pin Harn CLI instead of `<release cargo target>/debug/harn`, which Cargo republishes by overwriting in place. A concurrent release, recovery, or exact-tree build sharing that target directory was rewriting a binary other in-flight runs had mapped, and macOS killed those processes with `SIGKILL (Code Signature Invalid)`. The copy is keyed by pin SHA, installed through an atomic rename so restaging leaves a running process on its own inode, and lives outside the directories the cargo cache prune deletes.
