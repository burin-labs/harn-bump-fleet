Harn release preparation now requires exact successful Windows and macOS
workflow runs for the frozen source SHA, overlapped with the local source
audit. The closed receipt records exact run and job identities, branch
stability, timings, and the warmed binary hash; failed certification cancels
exact runs and the release commit must have the certified source as its sole
parent.

The release harness now consumes the GitHub connector's canonical `Result`
boundary directly, avoiding nested success variants during live release
analysis.

Certification now runs before release-branch or changelog mutation, retries
typed transient reads against the exact dispatched run IDs, and normalizes
numeric command statuses in recovery reports.
